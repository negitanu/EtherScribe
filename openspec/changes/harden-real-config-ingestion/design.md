## Investigation boundary
入力は利用者が置いたローカルディレクトリ `.data/`（または `data/`）だけ。内容・ホスト名・IP・オブジェクト名・元ファイル名・秘密値をツール出力や検証記録へ出さず、静的な構造名と件数・成否のみで比較する。解析結果はメモリ内で検証し、実データ由来のレポートは作成しない。

## Decisions
- ディレクトリ全体を gitignore で除外し、拡張子に依存せず実設定の追跡を防ぐ。
- 構造比較で見つかった不足を本設計に追記し、実装の前に要件とタスクを具体化する。
- 回帰 fixture は予約 IP・架空の識別子を使って独立に作成する。実設定の置換コピーやスナップショットは作らない。
- opt-in のローカル検証は利用可能な入力を順に検証し、失敗時も本文や例外文字列を出さない。通常の go test は実設定なしで成功する。

## Validation
実設定のソース件数とモデル件数の比較、合成 fixture の期待値、全 Go テスト、fixture key check、ビルド、OpenSpec strict、実設定の Git 非追跡を確認する。

## Observed structural gaps and implementation scope

- FortiGate: 最初の調査では同じ設定ツリーパーサ由来の件数同士が一致していたが、これは完全性の根拠にならなかった。VDOM の暗黙の edit 終端を誤解釈し、後続のアドレス・サービス・ポリシー・経路を読み落としていた。独立した構文スタックでソースの定義数とポリシー順序を検証し、暗黙終端と Go map 走査による順序の喪失を修正する。非 VDOM の不正終端は引き続き警告する。
- Palo Alto: Ethernet のみ取り込まれ、aggregate-ethernet と vlan/units が落ちる。物理・集約・VLAN・サブ IF、tap/layer2/layer3/virtual-wire のモード、LAG メンバーと VLAN の L3 関連付けを解析する。
- Palo Alto: 管理 IP／マスク／GW、DNS／NTP／タイムゾーンを取り込む。ポリシーの application、source-user、category、タグ、プロファイル、スケジュール・説明を保持する。IPv6 静的ルートのゲートウェイと出力 IF も既存の IPv4 と対等に扱う。
- レポートの固定列・日本語ラベルは追加フィールドにも適用する。
- 未実装の SD-WAN、スケジュール定義、認証、詳細プロファイルの完全移植は今回の解析完了と偽らず、部分対応／解析範囲に残す。

- FortiGate の未対応ブロックを global だけでなく各 VDOM からも集計する。VDOM 識別子は付録のパスに埋めず、`vdom/*/` と出現数で示す。Palo Alto も未モデル化の構造パスを集計し、entry の名前・本文・属性は含めない。
- 経路メトリックと管理距離を混同せず、独立したモデル項目として保持する。
- 検証用のソースカウンター自体も合成 fixture でテストし、実設定のエラー詳細と panic 値は匿名の区分に変換する。JSON/HTML/Excel はメモリ内だけで生成・検証する。
